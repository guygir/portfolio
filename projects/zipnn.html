ZipNN

Lossless compression built for AI model data.

1

Why this matters

As models grow, their size burdens the infrastructure that stores and moves them — more network, more storage.

One paper example: Mistral at 14.5 GB with 2.77 million monthly Hugging Face downloads is about 40 PB of transfer in a month.

Distillation, pruning, and quantization make a smaller model by throwing information away. ZipNN is the other kind of compression: a compact form plus a decompressor that returns the original weights.

Same bits back — decompress returns the original weights.

2

What we built

ZipNN is a lossless compressor tailored to neural-network tensors. An open library sits at github.com/zipnn/zipnn (pip install zipnn) and can keep models compressed on disk for Hugging Face, Safetensors, and vLLM.

The paper ZipNN: Lossless Compression for AI Models lists Guy Girmonsky among the authors, with an IBM Research affiliation, and the catalog places the work at IEEE CLOUD 2025.

3

How it works

Model weights are arrays of floating-point numbers. The exponent bits are highly skewed; the fraction often is not. ZipNN rearranges those bytes and spends entropy coding where it pays.

  1. Start from model weights (BF16 / FP32 tensors).
  2. Split bytes: extract the exponent, group the rest.
  3. Huffman / entropy-code the skewed bytes; skip incompressible parts.
  4. Store the compact form; decompress to the original weights.
1 · Weights Tensors of BF16 / FP32 parameters
2 · Split bytes Exponent out; remaining bytes grouped
3 · Entropy code Huffman on skewed bytes; skip the rest
4 · Store / load Compact on disk; original after inflate

4

Results

  • Often about 33% smaller; at times over 50% (clean models, e.g. RoBERTa around 55%).
  • Typical: BF16 ≈ 33% saved; regular FP32 ≈ 17%.
  • On Llama 3, more than 17% better space than vanilla compression, and 62% faster compress / decompress.
  • With several workers: up to 80 GB/s inflate, 13 GB/s deflate.
  • The paper estimates over an exabyte a year of Hugging Face hub traffic if methods like this were applied.

README single-thread BF16 check: ZipNN left 66.3% of the file; Zstd left 78.3%. LZ4 and Snappy left 100%.

5

What it is not

  • Not quantization, pruning, or distillation — those do not restore the original weights.
  • Not an inference-format shrink. It stores a compact blob; you decompress to run.
  • Regular FP32 models save less, because the exponent is only a quarter of the bits.
  • LZ-only tools (LZ4, Snappy) usually find no repeated multi-byte runs in tensors.
  • The published library is CPU today; the README says GPU work is on the way.

Bottom line

Same weights, smaller files. ZipNN is lossless compression for AI model data — IBM Research, IEEE CLOUD 2025.
